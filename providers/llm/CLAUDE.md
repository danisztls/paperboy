# providers/llm/

LLM adapter implementations and the `ModelSpec` capability registry.

## Provider docs

When in doubt about an adapter's API or model behavior:

- Gemini: https://ai.google.dev/
- DeepSeek: https://api-docs.deepseek.com/
- Claude Code CLI: `claude --help` (the `claude_cli` adapter shells out to the local binary)

## Files

- `__init__.py` — `get_adapter(provider, api_key)` factory; returns `GeminiAdapter` when `provider == "gemini"`, `ClaudeCliAdapter` when `provider == "claude_cli"`, else `DeepSeekAdapter` (the default). Also exports `FallbackAdapter`, which takes `list[tuple[adapter, model, default_reasoning]]` and tries entries in order until one returns non-None. Each entry carries its own default reasoning level; a caller's truthy `reasoning` arg overrides every entry (this is how `--analysis` forces reasoning on), while falsy/None lets each entry use its own default. `build_model_handle(specs, api_keys)` turns a `list[ModelSpec]` into a `ModelHandle` (single spec → adapter + model + reasoning; multiple specs → `FallbackAdapter` with per-entry model/reasoning; empty → None).
- `base.py` — `ModelHandle` frozen dataclass: a ready-to-call `(adapter, model, reasoning)` bundle passed around instead of three loose parameters; `reasoning_for(analysis)` encodes the `--analysis` override precedence. Plus the `LLMAdapter` ABC with two abstract methods: `complete(...) -> LLMResponse | None` for free-form text and `complete_structured(prompt, response_model, ...) -> BaseModel | None` for provider-native structured output. Both `complete()` and `complete_structured()` also accept an optional `messages` list (a full `{role, content}` conversation sent verbatim — `prompt`/`instructions` ignored, `system` turns fold into Gemini's `system_instruction`): the multi-turn path that holds a byte-stable leading prefix so DeepSeek/Gemini reuse their prompt cache across turns. `complete_structured(messages=...)` keeps the caller's conversation as the stable prefix and appends its JSON-schema ask as a trailing turn (so the cacheable prefix is identical across the action turns and the final verdict). Plus the `LLMResponse` dataclass (`text`, `model`, `input_tokens`, `output_tokens`, `latency_s`, `reasoning`, `finish_reason`, `cache_hit_tokens`, `cache_miss_tokens` — the last two report prompt-cache prefix reuse, the signal that multi-turn context is staying warm). Both methods accept `reasoning: bool | str | dict = False` — strings `"off"|"low"|"medium"|"high"` are the canonical form (set via `ModelSpec.reasoning`); booleans and dicts are accepted for back-compat and per-call overrides. The shared helper `reasoning_level(value)` returns the level string (or `None` for off); each adapter maps the level to its provider-specific shape.
- `models.json` — capability registry consumed by `config/schema.py`'s `ModelSpec` validator. Maps `provider → {model_name → {thinking: bool, deprecated?: bool}}`. Unknown model names produce a validate-time warning; `reasoning: low|medium|high` on a model with `thinking: false` is a hard error; `deprecated: true` entries still validate but emit a one-line warning so the user knows to migrate. Add new releases here so they validate cleanly. `claude_cli` lists the aliases `opus`/`sonnet`/`haiku`/`fable` plus full ids (`claude-opus-4-8`, `claude-sonnet-4-6`, `claude-haiku-4-5-20251001`, `claude-fable-5`), all thinking-capable.

## Adapters

- `gemini.py` — `google-genai`. Supports `ThinkingConfig(include_thoughts=True, thinking_budget=<per-level>)`. Structured output via `GenerateContentConfig(response_mime_type="application/json", response_schema=..., thinking_config=...)` — reasoning is plumbed through `complete_structured()`.
- `deepseek.py` — OpenAI-compatible Chat Completions (via the `openai` SDK pointed at `api.deepseek.com`). `complete()` toggles thinking per-request via `extra_body={"thinking": {"type": "enabled"/"disabled"}}` based on the resolved reasoning level. `complete_structured()` branches on reasoning: when truthy, delegates to `complete()` (which supports thinking) and parses the free-form response as JSON via Pydantic; when falsy, uses `response_format={"type": "json_object"}` with thinking disabled (the API rejects combining thinking with strict JSON).
- `claude_cli.py` — shells out to the local `claude -p --output-format json` (Claude Code CLI), prompt over **stdin** (never argv). Auth: **reuses the Claude Code login** by stripping `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` from the child env (so it bills the subscription's programmatic credit pool, not the API); an explicitly configured `llm.api_key.claude_cli` is injected back to opt into direct API billing. Runs hermetically (`--safe-mode --no-session-persistence --tools "" --disable-slash-commands`) — all three needed (verified by capturing the real request body): `--safe-mode` strips CLAUDE.md/memory/MCP, `--tools ""` removes the ~29 built-in tool *definitions* (`--allowedTools ""` is the wrong lever — it only denies permission, the schemas still ship and still bias the model), `--disable-slash-commands` drops the ~27 slash-command descriptions. Together this cuts a call from ~11.7K tokens of injected agentic context to ~160 (just our `--system-prompt` + data; a base "You are a Claude agent" line + billing header remain, a few tokens). The CLI never takes its own agentic turns — paperboy drives any loop, so the `messages` path is flattened to `--system-prompt` (leading system turns) + a byte-stable rendered body (`User:`/`Assistant:` blocks) that keeps the prompt-cache prefix warm. **No `--json-schema`** (it's ignored when tools are off): `complete_structured()` appends the JSON schema to the body and parses `result` with Pydantic (`_extract_json` strips stray fences/prose), mirroring DeepSeek's reasoning path. Reasoning maps to `--effort low|medium|high`. The envelope has no top-level `model` (→ falls back to the requested name); cache counts come from `usage.cache_read_input_tokens` (hit) / `input_tokens + cache_creation_input_tokens` (miss); `total_cost_usd` is logged per call (programmatic use is metered as of 2026-06-15) and captured into the trace as `cost_usd`. Fail-open: any failure (missing binary, non-zero exit, timeout, error/non-success envelope, unparseable output, validation failure) returns `None`.
